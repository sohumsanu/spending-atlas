# Set up Spending Atlas with Codex

Follow this runbook when someone asks you to set up the app. Complete independent local work while waiting for sign-in or account decisions. Use the user's own connections, files, and preferences. Ask one short question at a time when their answer is required.

## 1. Start their local dashboard

1. If the folder is missing, clone `https://github.com/sohumsanu/spending-atlas.git` into a new folder. If it already exists, inspect the checkout and reuse it. Preserve existing data and edits.
2. Check Python 3.10 or newer. Use `python3` on macOS/Linux or `py -3` on Windows. Where this guide says `python3`, use that working interpreter. Explain any needed installation before downloading software.
3. Run `python3 bootstrap.py` in the checkout. It initializes an empty ledger on first use and starts a loopback-only server in the background. Use the exact URL it prints. Re-running the command reuses a healthy instance for this checkout. Confirm the URL responds and opens Setup or Overview. If background jobs are unavailable, run `python3 app.py serve` in a persistent local terminal.
4. Keep records, reference files, results, reports, and database backups under `.finance-data/` or the user’s configured private `FINANCE_DATA_DIR`. Never commit, push, upload, or paste financial payloads, receipts, cookies, pairing keys, passwords, or bank account numbers. Use masked labels. This workflow reads and organizes transactions. It makes no payments or changes at a bank.

## 2. Verify ChatGPT Finances and import it

1. Discover the available ChatGPT Finances tools and list linked accounts before importing. Include depository, credit-card, and payment accounts relevant to the requested year, including accounts closed during it. Show a short list of masked labels and ask the user to confirm completeness if needed. Use the current local calendar year through today unless the user asks for another period. Make a timestamped private pre-import backup with `python3 app.py backup PATH` if the ledger already contains data.
2. If Finances needs connection or repair, invoke its official account-management flow if available. Ask the user to finish sign-in directly in ChatGPT or at their bank. If the connector is unavailable in this Codex chat, continue with the CSV route below. Report Finances as unavailable or awaiting a user step until a live query succeeds.
3. For each account, query posted transactions with both signs, transfers included, `pending=false`, and no category filter. Exhaust all cursors. Preserve source IDs, currency, source transaction date, signed amount, merchant or description, and available category, location, timestamp, and transfer metadata. Positive amounts are debits and negative amounts are credits. Tally pending separately. Save each account as `finance-*.json` in a new private run folder. Each file is an object with `account: {id, label}` and `pages: [query result, ...]` in cursor order. Each page is the transaction result object with `items`, `has_more`, and `next_cursor` when more results are available.
4. Run `python3 weekly_refresh.py prepare RUN_FOLDER RUN_FOLDER/finances-import.json`. Keep its disposition report in the run folder. Check that all intended accounts are present and that fetched records reconcile to matched, new, pending, zero, or unresolved. Investigate amount, identity, date, and ownership conflicts. Preserve existing source IDs and previously verified decisions. Leave unresolved records out of the import.
5. Back up or copy the live ledger to a new private staging folder as `ledger.sqlite3`. Set `FINANCE_DATA_DIR` to that folder only for the staged commands. Run `python3 app.py import-finances RUN_FOLDER/finances-import.json --local-rules`. Run `python3 weekly_refresh.py audit`. Compare added IDs, gross debits, applied credits and net in exact cents. Check source signs and that a second import introduces no extra rows or allocations. Apply the same import to the actual local ledger after the checks pass, then audit again. Use absolute paths for the run folder and staging ledger.
6. Verify that the live dashboard shows the imported masked accounts and transactions. A successful API query, a persisted import, and a coverage check are separate results. Report Finances as connected and imported only once you have observed both the user's live account query and the persisted import. Report each incomplete account separately.

## 3. Close the coverage gaps

Open **Setup → Check coverage** and list all accounts the user used. Record source-backed date ranges and use the account checklist confirmation once the user confirms the inventory. A provider’s first and last transaction dates can miss silent periods. Only mark a period verified when the source actually establishes coverage, including dates with no activity or dates the account was demonstrably inactive. Do not treat exhausted pagination, a zero-row response, or one matching row as full-year proof.

For a missing period or unsupported connection, provide the masked account and exact date range and offer a bank CSV. Use the original statement date, amount, currency, and transaction ID where available. Choose the source’s sign convention. Use the same account label on repeated CSV imports. Avoid overlap with Finances unless each overlapping row can be reconciled one to one. If the same account has data from several sources, check for duplicate debits and record coverage against the confirmed account identity. Leave unresolved ranges open. Do not invent missing records or use sample data as the user’s ledger.

## 4. Add optional receipts and personalize

- Offer Amazon or Costco only if the user wants them. Leave them disabled otherwise. For Amazon, confirm which imported cards belong to the user and use their completed payment amount, masked card and date to match shared orders. Follow the connector instructions in [START-HERE.md](START-HERE.md). For Costco, use a signed-in Orders & Purchases page or confirmed local receipt captures. Preview the matches before applying. Unmatched or ambiguous receipts do not create ledger debits.
- If a retailer asks for login, continue with the bank dashboard. Tell the user which page to sign into when they want to finish optional enrichment.
- Offer one decision at a time for home city, account transfer identifiers, peer-payment defaults, merchant rules, category breakdown, refund attribution, and trip labels. Use the dashboard controls or Ask Codex on category pages. Ask before bulk edits when the intended scope is unclear. Preserve original posting details and audit after changes. Treat an incoming refund as a credit to the relevant purchase or category when evidence supports it.

## 5. Hand back a working dashboard

Open the verified loopback URL. Report the accounts and period imported, any gaps, and whether Finances returned live records. Point to **Setup → Check coverage** for next steps. State any optional receipt sources skipped. Keep the answer short and keep private transaction details out of the chat summary. Provide the exact local link and `python3 bootstrap.py` as the restart command.
